# SOP与词库统一设计

用户已认可上一轮逐项审查及改进顺序，按现有 Python + GitHub Pages 静态页面实现。SOP采用独立页面，保持现有墨绿、暖白与中文衬线标题。词库仅导入用户页面内 V1.7 的元信息、词族和 A—F 原式，不执行材料内自动化指令。

SOP是操作规范和人工复核记录；实际采集结果仍来自雷达执行日志。项目台账统一使用现有项目库，不另建脱节的离线项目库。新增8阶段的输入、操作、产物、完成条件、失败处理；涵盖范围、检索分页、正文附件取证、分类归并、金额时间字段、发布验收、续抓与词库回顾。人工状态按北京时间自然周存储，完成须填写证据，备份可导入，保存失败须提示。

公开词库配置升级V1.7（190词），同时保留既有数据的V1.5提取与执行来源；历史记录不贴新词库标签。展示配置与最近执行版本差异和新增词。导入器拒绝旧版本覆盖新版本。生成最新A—F完整计划和宽母包补充计划；母包仅候选，不更改原串C，正文继续按原式核验。

发布独立sop.html并加入首页及实施方案入口，GitHub Pages部署包含页面和依赖；网页数据及周报继续标注最近实际采集时间。自动化提示读取新SOP，保留调度，先执行新版差异回补，再常规增量；不声明本轮SOP升级已重抓全年度。

选择复用当前项目；重建项目会重复已有正文与项目库，直接覆盖原材料则可能丢失用户原文件且临时地址不适合作长期入口。运行源码与公开镜像必须一致；原始页面和完整词库材料保留本地，不发布原材料。
