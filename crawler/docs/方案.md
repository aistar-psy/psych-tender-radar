# 心理健康教育采购雷达：独立实施方案

## 目标与范围

基于V1.3词库及已发现的公开公告，重建不依赖WorkBuddy的Python项目。覆盖能力采用可核验的来源任务账，不能将全国查询计划称为全网抓取成功。大陆31省级地区为基础，兵团/计划单列市和B端机构另列。教育核心、教育相关、其他心理、待核验和排除分组。

第一版实现可运行闭环：来源与搜索计划→公开来源发现→公告正文/附件存档→产品参数证据提取→SQLite去重与历史→分组周报/详情卡/覆盖记录。每周一9点调度运行，失败或无法取得附件写明。保留原任务和原文件，新项目单独保存。

## 架构与约定

- `radar/discovery.py`：加载词库；按地区轮询生成检索计划；来源目录和栏目发现；支持无需API的公开检索入口及可选搜索API；查询失败保留记录。
- `radar/documents.py`：HTML正文、表格及链接解析，PDF/DOCX/XLSX/ZIP内容提取；保留页码或表格行。没有OCR依赖或扫描PDF时标记待OCR，不捏造文字。
- `radar/analysis.py`：基于正文证据的确定性分类、项目元数据、产品/参数候选行、日期和金额口径；输出明确是“规则提取、待业务复核”，不冒充AI完整语义分析。
- `radar/fetch.py`：有请求间隔、超时、重试、大小限制、失败类型的HTTP抓取；原始证据与hash。
- `radar/store.py`：SQLite项目、公告版本、运行与待补；项目编号优先，缺编号谨慎去重。
- `radar/pipeline.py`：全流程预算、断点/失败保留、附件跟进、报告生成。
- `radar/cli.py`：plan/run/import-legacy/status；命令可独立运行。

文档接口：`parse_document(data:bytes, url:str, content_type:str='')->dict`，返回 `title,text,blocks,links,status,warnings`。blocks元素含`text,locator,kind`；links元素含`url,text,kind`，kind为attachment/page。压缩包内内容需要带文件名定位。
发现接口：`build_plan(regions:list[str], channels:dict[str,list[str]], start:str,end:str)->list[dict]`；每项含id,region,channel,query。`discover(query:str, fetch_callable)->dict` 返回status,links,error，fetch_callable(url)返回含body(bytes)、content_type、url、status_code的dict。来源栏目另走正文解析器链接发现。
分析接口：`analyze_document(doc:dict, url:str, now:str)->dict`，含title,project_number,published_at,deadline,category,category_evidence,products,parameters,amounts,warnings。参数保留locator和来源URL；数字不自动推导缺失预算。

## 默认运行与覆盖

全国基础检索按省份轮询、5通道检索；不依赖旧16条上限。默认每轮最多执行192个发现任务、读取40个公告，160个全国基础首组优先，余量轮转扩展；连续3次搜索失败熔断，保留正文抓取时间。每源请求至少1秒，超时15秒。未执行项在报告列明，持久游标让后续运行继续轮转；全国全量执行用显式更高预算。来源目录未验证入口标待配置，不作为成功任务。周报按发布日期窗口、历史补录、截止已过分开，不因最近抓到旧公告就称新增。

可选工作日增量不在默认调度内。每周一次会遗漏同周发布并截止的短窗口项目，报告说明这一能力边界。

## 验收

1. 查询预算16时至少覆盖16个地区，后续轮转不饿死尾部地区。
2. 普通病房家具排除；大数据中心采购校园心理归教育；医院儿少诊疗归医疗；关联画像无心理条款待核验。
3. HTML/PDF/Word/Excel提取有可追溯位置；附件失败不计正文完整成功。
4. 同项目重复URL/更正保留事件而项目去重，报告预算不重复加总。
5. 本地HTTP集成测试验证发现、正文、附件、失败、重跑去重，另执行真实公开源试运行。
6. 调度及命令说明可重复执行，运行日志和产物存在。不能取得的网站明确列出，不承诺100%全网覆盖。

## HTML与历史归档（2026-09-07）

首页提供本周（自然周）、近一年和日期待核验视图，归档保留跨周历史。日期缺失不冒充本周新增。项目表展示采购单位、主体性质、省份、公告标题链接、预算/限价/成交、发布日期、响应截止、明确开标时间。招标发布日期不能替代开标时间。

回溯使用 `--days 365`，本轮执行30条发现查询，形成43条去重候选，实际读取21份采购公告。连接或访问失败保留；全国各省公告库未逐页遍历，因此这些是已发现的年度线索，并非近一年全网总量。日期来源可为正文或明确标注的搜索索引日期，主体性质和分类是规则候选。索引字段可展示但不计入已核验金额。

`python -m radar.web_export` 将年度及每周运行记录归档到 publish/data.js，仅导出公开字段。所有历史运行参与归档，不能只取最近12次而丢失年度资料。网站由本地周一09:00自动化采集后推送，GitHub Actions部署页面；并非GitHub云端独立爬虫。

后续覆盖优化以官方来源连接器为主：逐省接入分页与时间筛选，记录成功页数/最早最后日期；并行保留学校、民办集团官网及聚合搜索补漏。每周核验未执行地区和失败URL，使用同项目编号关联采购意向/招标/更正/结果。建立按月、地区、主体、公告阶段的缺口，而不能以搜索命中量计算全网召回率。OCR、旧DOC/XLS/RAR和需登录付费采购文件仍是待补能力。

## 全国来源覆盖修正（2026-09-07 第二轮）

原版的两个单页采集入口不足以支撑全网覆盖。现在维护国家平台、省级政府采购、省级公共资源、计划单列市、商业聚合、院校自采及旧任务补充入口的独立台账。国家目录链接与现行公告域名分别记录，已修正多地迁移域名；目录有网址不能计作采集成功。

采集分为三个可复核步骤：`radar.source_scan` 对每站公开栏目和有限分页执行读取；按网站域名检索补充搜索索引线索；`radar.cli run --seed-file` 读取公告和可获取附件。分页预算外队列写入 remaining_urls，后续普通运行继续；`--resume` 仅用于本轮增补探测，不应用于每周跳过所有旧来源。省级查询、域名查询、首页连接、公告取得分别计数，带负号的排除站点不算定向检索。

本机连接失败不能等同没有公告。增加 GitHub 手动网络对照与公开正文补抓工作流，用独立网络读取公开URL；下载文件保留哈希、时间与来源，通过 `radar.cloud_replay` 导入，同样应用分类、参数证据和日期规则。它不登录、不付费、不替代需授权数据接口。云端首页200也不能证明正文或年度历史完整。

去重按统一URL与项目ID关联，跨运行保留公告事件及参数来源。最新公告元数据与历史参数分开；存在更正时金额汇总暂停，需核验字段生效关系。公告取得、请求失败、未执行、非采购排除分别统计。首页明确为当前入库量，不代表全国市场总量。

全量缺口仍包括：动态平台完整分页/站内接口、搜索未索引内容、县市自有入口、未登记院校/企业、会员历史库/采购文件及扫描件。每周追踪源台账缺口并追加来源，不能把某一轮清单宣布为所有网站全集。
